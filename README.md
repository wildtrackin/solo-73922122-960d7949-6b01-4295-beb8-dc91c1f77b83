# 植被调查离线修订合并平台

数据员把外业队的离线修订 CSV 并回当前记录库，供物种分布分析入库。
FastAPI + SQLite 实现，三方向（基线 / 修订 / 当前）逐字段合并，冲突人工裁决，整批事务化应用。
另提供**样方复核与核准**：复核员核对整份样方记录后核准，只有已核准样方的记录才进入核准 CSV 导出。

## 快速启动（Docker Compose）

```bash
docker compose up --build
```

启动后有**两个共库 Web 进程**（SQLite WAL 模式 + `BEGIN IMMEDIATE` 写锁串行化）：

- 进程 1：http://localhost:8000
- 进程 2：http://localhost:8001

两端共用同一数据卷中的 SQLite 库，可分别在浏览器操作，模拟并发核准、人工维护与离线合并。
SQLite 数据持久化在名为 `survey-data` 的卷中，**重启容器后核准状态与失效历史保留**；
首次启动自动载入 `data/initial_records.csv` 的 12 条初始记录，4 个样方初始均为**待复核**。

本地开发（可选）：

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload   # http://localhost:8000
```

## 数据格式

记录 = 唯一 ID + 样方 + 物种 + 非负整数株数。CSV 固定表头：

```csv
id,quadrat,species,count
R001,Q1,羊草,12
```

## 使用流程（网页四步）

1. **当前记录**：首页表格直接改值/删除/新增；`导出当前 CSV` 可随时下载。
2. **保存基线并导出**：点按钮把当前记录整体存为基线，并下载对应 CSV 交给外业队离线修订。
3. **上传修订**：选择该修订所基于的基线，上传外业队改完的 CSV。
   - 修订文件中**缺行 = 删除**该记录；**新 ID = 新增**。
   - 系统逐字段比较基线、修订、当前三方，生成合并预览。
4. **预览与确认**：
   - 不同字段各改各的 → 自动合并；双方改成相同值 → 只留一份；
   - 双方同字段改不同值、同 ID 新增内容不同、删除与修改相遇 → 展示三方值，逐项人工选择；
   - 全部裁决后一键**整批确认**，只应用离线改动。

## 样方复核与核准

顶部导航「样方复核 / 核准导出」进入复核页（`/reviews`），首页也展示各样方复核状态。

1. **复核页列出全部样方**：初始均为待复核；打开单个样方可查看该样方的**全部记录**。
2. **核准绑定所见完整成员和值**：提交时把当前全部记录（ID 集合 + 样方/物种/株数）规范化为
   快照哈希并持久化。复核期间可照常回首页编辑；提交时若**该样方**发生过新增、删除或改值，
   旧核准被拒绝，需按最新记录重新复核；**其他样方的变化不影响**本样方核准。
3. **核准后自动失效（立即转待复核）**：人工维护或离线合并对已核准样方造成
   增删、改值或记录迁入迁出时，该样方在**同一数据库事务**内立即转待复核并写入失效历史。
   - 改回原值、删除后同 ID 重建**都不能恢复**旧核准，必须重新核准；
   - 同值保存不产生记录变化，**不撤销**核准。
4. **核准 CSV 导出**（`/approved-export.csv`）：只含已核准样方的全部记录；
   复核页表格列出所有被排除的待复核样方。核准状态与导出记录在**同一读事务**内读取，
   取自同一已提交状态，不会放行未复核数据。
5. **失效可查**：复核页与单样方页均展示核准/失效事件（原因含新增、删除、改值、迁入、迁出、离线合并）。

### 并发与事务保证

- 所有写操作（人工增删改、合并应用、核准）均用 `BEGIN IMMEDIATE` 显式事务，
  进程内由锁串行化，两个 Web 进程间由 SQLite 文件锁串行化（`busy_timeout` 等待）。
- 记录变化与核准失效在同一事务提交：任何一步失败整体回滚，二者不会只生效一半。
- 核准提交时重新计算样方快照哈希并与页面绑定值比较，并发维护下要么拒绝旧核准，
  要么核准绑定的是最新已提交内容；因此核准导出在任何时刻都只包含有效核准覆盖的记录。

## 合并规则

| 情形 | 结果 |
|---|---|
| 仅修订改了某字段 | 自动采用修订值 |
| 仅当前改了某字段 | 自动保留当前值 |
| 双方改成相同值 | 自动保留一份 |
| 双方同字段改不同值 | 冲突，人工选修订值或当前值 |
| 修订缺行（删除）且当前未改 | 自动删除 |
| 修订删除 vs 当前已修改 | 冲突：删除 或 保留当前 |
| 修订修改 vs 当前已删除 | 冲突：按修订恢复 或 保持删除 |
| 双方各自新增同 ID 同内容 | 只留一份 |
| 双方各自新增同 ID 不同内容 | 冲突：二选一 |

## 过期保护与事务性

- 预览生成时对**计划触及的记录**拍快照；确认时重新核对。
  拟改记录在预览后又被修改或删除 → **拒绝旧预览**，按最新当前记录自动重新比较；
  **无关记录的变化不影响确认**。
- 整批应用在单个事务中执行，任何失败整体回滚，**当前数据不变**。

## 交叉修订演示样例

`samples/` 下有两队基于初始数据的离线修订，可直接在网页上传演示：

```text
1. 首页点「保存当前记录为基线并导出 CSV」→ 得到基线 #1
2. 在当前记录里把 R003 株数改为 7、R009 株数改为 8（模拟库内同期改动）
3. 上传 samples/team_a_revision.csv（选基线 #1）
   → 7 项自动合并（改 R002/R004/R005/R010、删 R008、增 R101/R102），无冲突，直接确认
4. 上传 samples/team_b_revision.csv（仍选基线 #1）
   → 自动合并：R005 物种改扁穗冰草（与 A 的株数改动字段级合并）、R007 株数、新增 R201
   → 冲突：R002 双方改不同株数；R003 队B删除 vs 当前已改；R102 双方新增内容不同
5. 先别确认：回首页把 R007 株数改为 20，再回预览点确认
   → 旧预览被拒绝并自动重新比较（R007 变成新冲突）；R009 等无关改动不阻碍确认
6. 裁决全部冲突后确认 → 整批应用
```

## 项目结构

```text
app/
  main.py        FastAPI 路由：记录维护、基线、上传、预览、确认、样方复核、核准 CSV 导出
  merge.py       三方向逐字段合并与冲突裁决合成
  csvio.py       修订 CSV 解析（校验非负整数株数等）与导出
  db.py          SQLite 访问层；显式事务、核准快照哈希、失效联动、合并单事务应用
  templates/     页面模板（reviews.html 复核列表、review_detail.html 单样方复核）
tests/           复核/核准端到端测试（pytest + TestClient）
data/initial_records.csv   初始数据（首次启动自动载入）
samples/                   两队交叉修订样例
Dockerfile / docker-compose.yml   两个共库 Web 进程（端口 8000 / 8001）
```

### 数据表

- `records` / `baselines` / `previews`：原有记录、基线与合并预览。
- `quadrat_approvals`：样方核准，保存核准时间、完整快照 JSON 与快照哈希（主键为样方名）。
- `approval_events`：核准与失效历史（kind=approved/revoked，含原因与说明）。
